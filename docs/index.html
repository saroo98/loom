WHY LOOM / THE TERRAIN CHANGES

A plan is trustworthy only while it describes the same world.

Loom does not turn your request into a longer prompt. It turns the current project into a content-bound execution contract and refuses to pretend when the evidence changes.

01

See the whole world

Committed, staged, unstaged, untracked, generated, invalid, and time-drifted state belong to one bounded observation.

Prevents planning the wrong repository.
02

Use the domain’s rules

Accounting, real-time 3D, firmware, research, and unfamiliar fields receive different invariants and proof media.

Prevents web-shaped plans everywhere.
03

Seal before building

Artifacts, touched paths, work-order content, gate records, and acceptance evidence are bound before implementation earns credit.

Prevents the plan moving after approval.
04

Prove in the real medium

A written “passed” flag cannot replace the device, browser, ledger, pipeline, or runtime that must actually work.

Prevents ceremonial verification.

FAIL CLOSED / THE USEFUL PART

What Loom refuses is part of the product.

The world changed

Reobserve and re-gate. Never execute a plan for an older repository state.

The domain is unknown

Discover authority, invariants, and proof. Never substitute generic defaults.

The plan changed after approval

Block execution. Authorization belongs to exact content, not a filename.

The evidence is only prose

Refuse completion. Real-medium results must bind to the work that produced them.
