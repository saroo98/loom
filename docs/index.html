The missing layer

A strong model can still start with the wrong picture.

A prompt rarely contains the whole project. The repository may have uncommitted work, local rules, architectural boundaries, unresolved assumptions, and checks that only make sense in the real runtime.

Loom brings that information into one planning decision before implementation begins.

Without Loom

Request → generic plan → files change → missing context appears late

What happens before coding

One request enters. A project-specific plan comes back.

  1. 01

    Read the current project

    Loom examines committed, staged, unstaged, and untracked state together with the project instructions that apply.

  2. 02

    Separate facts from unknowns

    Known information stays distinct from assumptions. Every important assumption receives a way to verify it.

  3. 03

    Shape the work to the real risk

    Small work stays compact. Consequential or unfamiliar work receives the additional planning and domain checks it needs.

  4. 04

    Stop for your review

    You see the proposed work, affected files, assumptions, and completion checks before implementation is authorized.

What every useful plan answers

The questions an agent should answer before touching code.

01 What exactly will change?

Concrete steps and a bounded work order replace open-ended implementation intent.

02 Which files may be affected?

Likely touch paths are named so unrelated changes are visible before and during implementation.

03 What is known, assumed, or still unknown?

Evidence, assumptions, and unresolved decisions remain distinct instead of being flattened into confident prose.

04 How will completion be checked?

The plan names the tests, runtime checks, or other real medium required to demonstrate the result.

One Loom, shaped for its owner

Keep the judgment that helps. Leave the rest behind.

Loom can retain bounded local preferences and measured outcomes. General judgment, domain knowledge, and project memory remain separately scoped so one project does not become a rule for every project.

Learning stays on your device. Loom sends no telemetry and excludes owner state from the public package.

3
