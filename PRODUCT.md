# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Loom serves people who delegate software work to AI coding agents and need the agent to understand
the current project, choose an appropriate planning depth, produce executable work orders, verify
real outcomes, and retain only useful owner-specific learning.

The public website and README serve two audiences: a first-time adopter deciding whether Loom is
trustworthy, and a technical evaluator checking how its safety and learning claims are enforced.

## Product Purpose

Loom is a local-first planning intelligence layer for AI coding agents. One plain-language request
becomes a current, domain-aware, evidence-backed plan that earns implementation authority only
after mechanical checks pass.

Success means small work stays small, consequential work receives proportionate scrutiny, stale or
unknown state blocks safely, and useful owner learning improves future work without becoming an
unbounded context or privacy cost.

## Positioning

Loom combines live repository state, bounded domain discovery, consumer-driven planning artifacts,
causal work-order authorization, real-medium verification, and scoped local learning behind one
`/loom <request>` surface. Its public claims are tied to shipped schemas, tools, tests, and signed
release evidence rather than marketing assertions.

## Operating Context

- Loom is installed as a local Codex plugin or used through supported local agent adapters.
- Mutable owner state lives outside immutable runtime versions.
- The owner interacts through one plain-language Loom request.
- The runtime inspects the project, selects scope and domain evidence, authors a sealed plan, and
  records bounded outcomes and learning locally.
- Releases use signed immutable artifacts, reproducible native helpers, privacy scanning, rollback
  support, and exact-main CI evidence.

## Capabilities and Constraints

- Local-first storage with no Loom telemetry.
- One visible command surface.
- Tiered planning that scales with consequence and uncertainty.
- Unknown-domain discovery that does not pretend unsupported knowledge is verified.
- Atomic plan authoring and evidence-bound work orders.
- Scoped general, domain, project, component, temporary, and device learning.
- Bounded active memory and forgetting mechanics.
- Signed, staged, reversible upgrades with owner state stored separately.
- Honest limitations: external hostile review, current exact-host receipts, and some platform
  claims remain explicitly unverified where the release has no qualifying evidence.

## Brand Commitments

The product name is Loom. The public voice is direct, exact, calm, and evidence-led. The central
metaphor is not decorative weaving; it is a living intelligence that continuously brings request,
world state, domain knowledge, plan, evidence, and owner learning into alignment.

The surface must avoid generic AI imagery, inflated superlatives, invented adoption claims,
fabricated testimonials, and visual conventions that make trust look like hype.

## Evidence on Hand

- Signed release artifacts and release subjects under GitHub Releases.
- Mechanical capability registry at `docs/capabilities.json`.
- Generated repository inventory at `docs/generated-evidence.json`.
- Public limitations at `docs/limitations.md`.
- Architecture and verification documentation under `docs/`.
- CI workflows for fast gates, exact-cut matrices, native compatibility, and release attestation.
- No customer logos, usage metrics, testimonials, or third-party validation may be invented.

## Product Principles

1. Earn authority from current evidence.
2. Make the safe path the simple path.
3. Adapt deeply without contaminating scope.
4. Keep private owner intelligence sovereign and bounded.
5. Say exactly what is proven, unknown, reversible, and next.

## Accessibility & Inclusion

The public website must remain usable with keyboard navigation, reduced motion, high-contrast
settings, screen readers, mobile viewports, and zoomed text. Motion may demonstrate Loom's living
behavior but cannot gate access to content or actions.
